# Private portfolio analytics setup

Status: configured locally with Measurement ID `G-4240R0VBXR`, supplied in the owner's GA4 stream screenshot. The stream URL is `https://sathishveerapathiran-portfolio.netlify.app/`. Collection begins only after the updated files are deployed and the visitor allows analytics. No live Google collection, dashboard access or deployment has been verified.

1. Sign into https://analytics.google.com/ with your own Google account.
2. Create an account/property called Sathish Portfolio. Choose the reporting timezone and business details that apply to you.
3. Use the Web data stream for `https://sathishveerapathiran-portfolio.netlify.app/`.
4. Turn OFF Enhanced Measurement in the stream settings. This integration sends its own limited events; automatic form interaction/download tracking would add separate counts and could collect unintended form metadata. Leave Google Signals/ad features off for this implementation.
5. Copy the Web stream Measurement ID beginning `G-`. Put only that ID in `analytics-config.js`, replacing the empty string. Do not add a second Google tag snippet to the HTML.
6. Publish `index.html`, `analytics-config.js`, `analytics.js` and `refinements.css` together. The resume and existing JS files remain necessary.
7. On the live HTTPS page, allow analytics, visit the page and click the resume/email/contact links. Check the property’s Realtime report for events. Standard reports can take longer to populate. Verify in the actual Google account before calling setup complete.

## Counts and privacy

The footer's Owner analytics dashboard link opens Google Analytics, where Google account/property access controls protect the reports. The link itself is public; counts and credentials are never embedded in the portfolio. Do not make reports public or grant access to others if you want owner-only access. An inline authenticated dashboard would require additional backend/authentication infrastructure; no fake hidden dashboard or client-side password has been added.

Use Users for measured visitor estimates, Views for page views and Sessions for visits. These are different metrics. Cookie choices, browser restrictions and ad blockers mean measured users are not an exact headcount and not every visit can be counted. Local previews and HTTP pages are excluded. No historical traffic is recovered.

| Event | Counts |
| --- | --- |
| `page_view` | Page views after consent (generated by the Google tag configuration) |
| `resume_download_click` | Resume link activations, not completed downloads |
| `email_click` | Email-link activations; `audience` is hiring or business |
| `contact_click` | LinkedIn/WhatsApp link activations; `channel` identifies which |
| `contact_draft_request` | Valid contact-form requests to prepare an email draft, not received enquiries |

Read event counts in the Events report. For breakdowns, register event-scoped custom dimensions for `audience`, `channel` and `placement` in GA4, then use Explorations. Do not sum all categories and label them unique leads: one visitor can perform several actions.

The analytics script starts only after permission, with a footer control to change the preference. Event parameters contain category labels only, not form names, email addresses, message text or mailto URLs. Page URL query and fragment are stripped; page referrer is not sent by this configuration. Google still processes normal analytics/device/network information according to its service. Browser-stored preferences are not shared counters.

Verification: `node verify-analytics.cjs` uses test doubles and does not contact Google. `python verify.py` checks referenced local scripts/assets. Live GA delivery, actual reporting permissions and browser rendering remain pending.
